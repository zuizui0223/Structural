# Wetherbee et al. 2023 Norway 270: author R join argument grammar × site-info original resource header qualification (prebiology gate, 2026-11-17)

## What is already source-verified

Original Wetherbee 2023 forest naturalness study [DOI 10.1002/ece3.10739](https://doi.org/10.1002/ece3.10739) reported 270 source sites across eight historical 1997–2007 projects, 339 obligate saproxylic beetle species, and published predator relative abundance and morphological predictors. Its [Zenodo DOI 10.5281/zenodo.8272489](https://doi.org/10.5281/zenodo.8272489) original public eight-file manifest and original published MD5s were verified in previous source-only CI runs.

- Three original CSV files (all 2023 published MD5 verified, row values NOT opened): `GBIFnormalized_SpcSite_matrix_FD_unique.csv` (2,759,229 bytes; 1,090 original columns), `GBIFnormalized_Trait_RAW_df.csv` (485,427 bytes; 64 columns), `SiteInfo_Alltaxon_Pred_Detri_SxFD.csv` (403,751 bytes; 41 columns).
- Two original author R source files (MD5 verified): `DataAnalysis_FT_with_BioDmeasures.R` (6204 bytes, md5 b5b02af2b3c07e741fe1e1afc3d022a5), `Ord_SO.select.R` (8148 bytes, md5 871e3eb4ff24af8860f553fbd89b5b75). [Original R grammar source-only run #44083524412](https://github.com/zuizui0223/Structural/actions/runs/44083524412) found five reader calls, two merge calls, eight name operations, three transpose-like operations, and references to the three source filenames in the latter script. **This is not a proven join.**
- Older Norway Burner 468-site collections may overlap or completely contain 270 Wetherbee sites; the source cannot be classified as independent replication without original project/physical-site lineage.

## Exactly one new source-only method-quality diagnostic

**Question:** Does original author R code explicitly define a deterministic *project×physical site/year* crosswalk and is there an original site-info field that explicitly measures **local host tree/deadwood resource abundance/identity** (not merely source `tree` as a trap-hung host type)?

1. Download **ONLY** the two exact original author R scripts and SiteInfo CSV from official public Zenodo record 8272489, using previously verified source sizes+MD5; one normal GET per file, no retries/host/path variants. Original source bytes remain runner-private. Script text is parsed lexically/static **not executed**; SiteInfo CSV is inspected for its first HEADER line only, no sample/site/species/trait or environmental numeric data rows read.
2. Implement an R lexer that recognizes comments, quotes and balanced nested parentheses, then extract **all actual call argument structures** of `read.csv/read.table/read.delim`, `merge`, `left_join/inner_join/full_join`, `rownames/colnames`, `paste/paste0` and `t` (no evaluation). Preserve only callee type, argument names, count of positional args, generic/safe exact file-reference booleans, a whitelisted *generic* literal join key if present, and abstracted syntax class for join keys (literal string, vector literal, expression, missing). Output **no original source code, line expressions, raw non-whitelisted field names, site IDs, taxa, tokens or values**.
3. For every merge/join call: distinguish explicit `by=`, `by.x/by.y`, `by_join` vs implicit common-name merge; count explicit source-key strings only when they fall within safe generic vocabulary `site, siteid, plot, plotid, project, projectid, study, studyid, year, sampleid, tree`. Never promote mere merge-call count into proof of physical-site identity.
4. Original SiteInfo CSV: verify original MD5 and 41-column header; inspect first line only. Classify header candidates by **strict exact predeclared generic key names** and **small predeclared lexical stem families**: parent project/study; site/plot; year/time; trap/effort; local resource/deadwood **physical amount** (`deadwood, dwvol, woodvolume, treebasalarea, standingdead, downedwood, volume, basalarea, snag`); forest stand class/naturalness; ecological trait. Report ONLY per-family counts and whitelisted generic header matches, never raw unfamiliar field names (site labels, taxon labels, source code).
5. **Science gate**: at least one *unambiguously named measured local deadwood/tree-host amount or identity* AND exact author site/parent-project key/crosswalk derivation AND independent lineage vs previous Burner original source AND effort/zero-capture source definition are jointly required **before any new species response fit**. Otherwise classify `SOURCE_ORIGINAL_HOSTWOOD_OR_PROJECT_CROSSWALK_NOT_YET_VERIFIED`. The presence of `tree` alone means nothing about local deadwood.
6. Source-only failure is not a biological null or a new positive. No species, guild, capture data, source environmental rows or original historical Burner matrices may be read in this gate. No eBird/TinyFish, no source author contact, no PR merge, no previous German/Piccini, Finnish, BALA or GEB heldout rescoring.

## Outcome boundary

If the source R program uses implicit joins or only site-name positional ordering, **do not make a new identity mapping from row order or 1,090 original wide columns**. Even an explicit `by="site"` is only an algorithmic key expression; it does not prove correct origin, sampling effort, source species-by-site equivalence or that the forest `tree` field measures live/deadwood composition.

This is a new method/code reading gate fixed before original field data or biological response inspection. Its findings must be archived anonymously and reported as source-eligibility only.
