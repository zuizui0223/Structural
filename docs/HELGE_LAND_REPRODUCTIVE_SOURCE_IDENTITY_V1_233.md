# Helgeland v1.233: is breeder output really linkable to observed immigrant origins?

The original author repository contains `nestling_producers_2007_2014.txt`, Git blob e6cc1558..., a published, individual-year source for offspring production `N_nestlings` and `N_Recruits` used in the original BRMS models. This may connect natal emigration observations with subsequent offspring counts—but the presence of reproductive count columns is **not** proof of a consistent marked bird ID join, of genetic parentage or of an immigrant's contribution to population rescue.

The unusual original file has 24 header labels but a 25-value data row with a leading R-export row number. The source parser must drop **only** that exact index field, then identify `ID`, `Year`, `Island` in source-locked data. Match to the original presence data's unique stage=nest birth year/island, and a **single** next-year observed capt/obs destination. Only first adult-year within 2007–2014 can match the producer table. All 11 islands are retained; ambiguous origin or destinations stay excluded and counted. No reproductive variables are read in this v1.233 audit: a match is merely a potentially analyzable ID-year-island.

Because Ranke et al. 2021 and Hansson Frank et al. 2026 studied this SAME population, any future comparison between migrant and resident reproductive production will be postpublication and non-independent. It must adjust stage, exposure, detection, reproductive effort, sex, age and origin/destination ecology, and first establish the source-specific meaning of `N_nestlings` and `N_Recruits`. This gate neither verifies offspring parentage nor estimates island demographic rescue. A low join rate is a substantive STOP—not a reason to fabricate ID crosswalks.
